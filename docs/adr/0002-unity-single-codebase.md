# 앱은 Unity 6(URP) 한 벌로 만든다

v1은 iOS와 안드로이드에 출시하고, 모든 기기에서 같은 장면을 보여 줘야 한다(ADR 0001). 장소와 캐릭터를 따로 팔고, 캐릭터 여러 명이 장소별 활동 애니메이션을 함께 써야 한다. 그래서 웹앱도, 네이티브 두 벌도 아닌 Unity 6 + URP 한 벌로 만든다. 렌더러가 하나라 두 OS에서 같은 결과가 나오고, 구운 조명, 사람형 애니메이션 공유, 추가 콘텐츠 다운로드를 엔진이 갖추고 있기 때문이다.

## Considered Options

- **웹앱(+Capacitor)**: 작성자가 웹 스택에 가장 익숙하다. 하지만 3D 성능 여유가 가장 적고, iOS 홈 화면 웹앱에서는 카메라 권한 창이 반복해서 뜬다. 작성자가 처음부터 웹앱은 쓰지 않기로 했다.
- **React Native + R3F(expo-gl)**: 작성자가 RN으로 앱을 낸 경험이 있다. 하지만 expo-gl 위의 3D에는 제약이 있고, 감지 기능을 네이티브로 따로 만들어야 한다.
- **네이티브 두 벌(RealityKit + Filament 등)**: 각 OS에서 가장 가볍다. 하지만 렌더러가 달라 셰이더와 조명을 두 번 맞춰야 해서 ADR 0001을 지키기 어렵다. iOS의 SceneKit은 이미 소프트 디프리케이트됐다.

## Consequences

- 감지는 MediaPipe Unity 플러그인을 먼저 쓴다. M1에서 막히면 iOS Vision과 Android ML Kit 네이티브 플러그인으로 바꾼다.
- 모델링과 텍스처는 Blender에서 하고, 조명 굽기는 Unity에서 한다. 시간대 혼합(라이트맵 여러 장)을 엔진이 관리해야 하기 때문이다.
- 모든 캐릭터는 사람형 뼈대 하나를 공유한다. 장소별 활동 애니메이션은 장소마다 한 번만 만든다.
- C#과 Unity를 새로 배워야 하고, 앱 용량이 커지며, UI도 Unity 안에서 만든다.
- Unity Personal(매출·투자 연 20만 달러 미만 무료) 조건 안에서 시작한다.
